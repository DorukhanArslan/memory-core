## Actual owners, public tools and effective profile

Native executes the original public manager facade and `memory_search` factory.
The SDK executes its real managed SQLite store and `create_memory_search_tool(...).execute(...)`.
Both use three foreground owners: producer, separate inspector, fresh default search owner.
The producer publishes through its supported sync/reindex API, runs a real same-owner
positive-control tool search, and closes before the declared SQLite metadata mutation.
The inspector reads status twice and closes. The fresh search owner reads status twice,
runs its actual first public tool query, reads status afterward, then closes.

Native inspection uses its real `purpose:"status"` owner. The SDK has no equivalent
read-only-purpose constructor: its separate managed owner performs status-only operations;
physical snapshots verify unchanged logical publication, not an equivalent write-refusal API.
Native may also acquire its genuine internal maintenance manager, linked to its actual foreground source owner.
The SDK retains its own background workers; no artificial fourth SDK manager is inserted.
Original method call-through receipts bind both public searches to their actual sampled owner.

The explicit profile is provider-none, vector-disabled, root `MEMORY.md`, indexed memory
plus an actually empty session corpus, and public query `corpus:"memory"`, maxResults 5,
minScore 0, rememberAcrossConversations false. It makes no paid provider calls.
The SDK explicitly selects `OpenClawCompatRuntimeIdentity` and publication `on-search`.
Source mutations and mtime setup finish before default acquisition; source bytes then remain unchanged.
The paired wall clock fixes `Date`/the supported SDK clock; timers and monotonic clocks remain real.

Native source hardcodes search/session sync, watchers, hybrid search, MMR and temporal decay on.
Ignored override requests are not presented as effective settings. Evergreen `MEMORY.md`
and the fixed clock avoid score drift without claiming temporal decay was disabled.
Missing or older metadata may be repaired by the actual first search. No post-mutation
manual sync, reindex or forced drain supplies equality. Each first tool dispatch calls
the genuine manager/store search once, including paused/unavailable results.
“Before query” means caller-visible diagnostics precede that dispatch; internal speculative
FTS/SQL preparation is possible and is not claimed absent.
