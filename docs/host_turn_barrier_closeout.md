## What the four cases establish

The frozen family contains `host-turn-barrier-cold-ascii`,
`host-turn-barrier-warm-ascii`, `host-turn-barrier-cold-unicode` and
`host-turn-barrier-warm-unicode`. Each drives a genuine save and immediate
follow-up in the same real host session. The follow-up starts on the first host
return, without intervening fixture synchronization, rebuild, dirty mark,
maintenance wait or timer drain. All four exact cases must match and validate
runtime custody together; incomplete or unverified subsets earn no point.

Cold cases commit the fact and retrieve it through actual search/get. Warm cases
first save an unrelated fact and retrieve it, establishing a populated index.
They then commit the new preference. The immediate warm query genuinely returns
**zero hits for the new fact** from the previously published generation, while
the source file already contains it. This is faithful bounded tool behavior,
**not a guarantee of immediately fresh recall** after a warm save.

The same chat history and current workspace context legitimately contain saved
facts. The fixture replies must use actual `memory_search`/`memory_get` results;
their binding to the full reply is checked by the custody guard. Warm emptiness
does not prove that an ordinary language model could not answer from its history
or current prompt. No real-LLM answer-quality or general recall claim is made.

The comparison preserves complete public search results, actual get results or
their genuine absence, and the complete host reply. Scores, provenance, debug
fields, warnings and carriers are not removed or repaired; there is no numeric
tolerance. Native coding `write` and SDK `add_memory_entry` are declared corpus
producers. Their different raw receipts remain custody evidence rather than a
claim that the producer APIs are interchangeable.

## Explicit profile and production changes

Provider-none refers to memory search/indexing. Language-model transport is a
local **scripted provider**, registered through the original plugin loader;
no paid calls occur. Native watch/on-search synchronization keeps its original
defaults. The SDK explicitly selects
`ManagedHostSession.open(..., memory_publication="on-search")`.

The default `"on-write"` managed policy and eager host APIs keep their behavior.
The new option commits curated changes and reports pending without forcing
publication in the writer turn or before the next model. Actual source hashes,
sizes and modification times are compared with published memory rows. Cold/empty
search still performs genuine bootstrap. A warm search pins its actual SQLite
generation, then admits a memory-only background publisher. Publication does
not replace that reader's results. Sessions retain their separate owner/queue.

Close joins admitted memory publishers, including queued work whose thread has
not entered. It does not publish dirty memory that no search admitted. Actual
failures remain visible as stale state until matching real publication recovers.
Submission failures do not masquerade as attempted SQL writes. Sessions-only
and empty/path-limited refreshes cannot certify a failed whole-memory job.
Explicit reindex/synchronize remain actual stronger publication operations;
they are not inserted into the compared host sequence.

Review reproduced an error-ordering race: an older worker could restore an error
after newer matching publication recovered. Live outcomes now settle under the
same workspace guard as actual source/SQL work; final settlement updates only
the historical job receipt and custody. A real journal-failure regression holds
the older worker, performs real newer recovery, then prevents error resurrection.
Other regressions cover a real closed-executor refusal and real WAL publication
while the first reader still holds its old SQL generation.

## Original caller and fixture boundaries

Native execution calls the original full `runReplyAgent`, including actual
foreground admission, without supplying a replacement reply operation. A
separate minimal provider plugin and narrow preload supply scripted transport
while retaining original host/tool execution. Source and official compiled
artifact provenance are authenticated separately; no independent source build
is claimed.

The declared wall clock replaces Native `Date` only, inherited by processes and
workers; the SDK uses its public host clock argument. Monotonic clocks and timers
remain real. Declared `os.utime` fixes source atime/mtime inside each actual
producer callback, after its real tool result and before its terminal reply.
It changes no source bytes and performs no index operation. It is never inserted
between first host return and follow-up. Teardown joins follow the fixed public
outcome; they do not make the compared answer fresh.
