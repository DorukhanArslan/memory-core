# Parity Matrix: memory-core against OpenClaw memory-core

This matrix preserves the v2026.9.6 baseline and its historical evidence. It is
not acceptance evidence for v2026.9.9. The current target, cleanup order, and
remaining acceptance work are tracked in [Full Equivalence Checklist](full-equivalence-checklist.md).

Purpose:

- Track the Python port against real OpenClaw TypeScript behavior, not against a guessed spec.
- Prefer executable oracle operations whenever a behavior can be isolated from the OpenClaw monorepo.
- Keep runtime-only OpenClaw features out of the port until they affect observable memory-core behavior.

Status legend:

- `match`: Python and OpenClaw are currently equivalent for the covered fixture.
- `mismatch`: Oracle comparison exists and shows a real difference.
- `partial`: Python implements part of the behavior, but oracle coverage or important edge cases are missing.
- `missing`: No meaningful Python equivalent yet.
- `out of scope`: OpenClaw runtime or platform feature not planned for the plug-and-play memory-core port.

Evidence standard:

- A row may say `match` only when an executable oracle operation exists and integration tests compare Python behavior against the pinned OpenClaw TypeScript checkout for the behavior described in `Known gaps`.
- Source-reading alone is not enough for `match`; it is `partial` unless the Python behavior is also isolated and tested against the TypeScript implementation.
- Demo-only behavior must be called out as an approximation and must not be presented as OpenClaw parity.
