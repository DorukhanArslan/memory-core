## Supported profile and physical layout

All members use provider none, disabled vectors, the OpenClaw compatibility
runtime identity, the existing on-search memory publication policy, memory and
session sources, and independently persisted original session metadata/events.
Provider-none search and deterministic external consolidation responses are
distinct inputs.

Native always uses its original shared index/origins agent database. The SDK
storageProfile declares the physical layout correspondence explicitly:

- Shared explicit-fence members use the same index/origins file, an actual
  `ledger.revision_fence(agent)`, and the supported
  `MemoryWorkspace(..., is_session_forgotten=...)` callback reading that ledger.
- Split explicit-fence members use separate index/origins files with the same
  supported public fence/callback wiring.
- Unfenced members retain the existing on-search policy and supply neither
  extra fence nor callback. They expose the existing default integration gap
  within this family.
- The SDK persisted session catalog always uses a separate file because its
  `memory_session_tombstones` schema differs from the origins ledger schema.
  No fixture mirrors ledger tombstones into that catalog.
- The SDK owned index connection enters WAL before any producer through a real
  PRAGMA whose receipt is retained. This matches the original Native reader
  concurrency surface and permits the genuine keyword/enrichment race. It
  creates no semantic row or revision.

The public SDK entry points are the actual managed store/workspace constructors,
original search tool, original reindex, original forget and original promotion.
The fixture must not claim that Memory.from_workspace or managed host opening
automatically supplies the explicit callback/fence.

Preparing host inputs persists the declared session facts exactly once through
original producers. The seed-actions step subsequently dispatches only its
labelled original recall calls. Every actor used by overlapping original calls
explicitly acquires its owner before conflicting gates, with its own receipt.
This prevents original store schema initialization from blocking before the
declared forget API has even entered. Starting a fresh process creates an inert
process, with subsequent explicit or first-call acquisition recorded separately.

## Clock, comparison and custody frozen before engines

The base wall time is 2026-11-14T00:00:00.000Z
(`1794614400000` milliseconds). Native Date wall-clock reads and SDK time.time
wall-clock reads use this declared input; actual monotonic clocks, SQLite waits,
watchdogs, process deadlines, watcher timers and debounce behavior remain real.
Tombstone createdAt values are compared whole, never stripped.

The original Native workspace lock checks a sixty-second age before dead-PID
recovery. After actual forget-child termination and reaping, marker-kill members
declare wall time 1794614460001 milliseconds for the already-pending builder at
gate release and each newly started recovery process. This literal 60001 ms
phase advance changes only wall-clock reads, including explicit original API
now arguments. It never deletes lock rows, changes real monotonic waits,
replaces the original captured revision or refreshes a stale prepared object.

Comparison retains whole original forget reports, whole public search details,
warnings/actions/errors, whole promotion results/events, source bytes, logical
origins/tombstones including timestamps, and all selected physical SQLite/raw
producer state. Errors and absent fields remain intact.

Sync uses PR17's previously declared common settlement projection
`{status,isTypedConflict}`; the actual Native void return, SDK integer and
complete private errors remain raw. No public search error, warning or action
is rewritten. The established JSON comparison treats 1 and 1.0 as equal numbers,
keeps booleans distinct, and uses no epsilon, rounding or string coercion.

The exact common top-level fields are `provider`, `calls` and `snapshots`.
Provider comes from the actual original index provider, which is `none` in this
profile. Calls are keyed by the declared namespace `kind:label`, where kind is
`sync`, `search`, `forget`, `promotion` or `recall`. This keeps `sync:seed` and
`promotion:seed`, and `sync:fresh` and `search:fresh`, distinct. Each call has
exactly `operation`, `label` and `outcome`; operation is that declared kind and
label remains the exact input API label. Raw custody binds its triggering step,
actor and original entry. An await step creates no second call.

Sync outcomes have exactly `status` (`fulfilled` or `rejected`) and
`isTypedConflict`. Recall-only fulfilled outcomes have exactly
`{status: "fulfilled"}`; rejected recall outcomes retain the actual public
message and code only when present. The original Native recall API returns

Whole actual recorded/skipped recall notifications and complete recall, origin

All other completed public outcomes have exactly
`{status: "fulfilled", result: <whole actual public result>}`; search result is
the complete actual DETAILS object, with its whole envelope retained raw.
Public rejections have exactly `{status: "rejected", error: <actual public
message and code when present>}`. Absent code stays absent; no string substitutes

identity. The actual full error, stack, prototype and private fields remain raw,
