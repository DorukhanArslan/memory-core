## Search effects are an explicit input control

The literal `observationPolicy.searchEffects.protocol` is
`original-search-effects-v3`. Each new step has exactly:

```json
{"operation":"await-original-search-effects","actor":"foreground","label":"seedSelected"}
```

Actor and label bind the exact earlier settled search in the same actual owner
lifetime. A synchronous `public-memory-search` gets one barrier after its real
public fulfillment or rejection. A `start-public-memory-search` gets no
barrier at start or while held; its one barrier follows the actual
`await-public-call` settlement. An earlier settled search must finish its
explicit barrier before physical capture or original owner close. A still
held search may remain pending at an intermediate capture, as case 10 requires.
No runtime choice may move a barrier or reorder an existing business step.

Passively capture the actual search-admitted recall promise/Future and original
already queued publisher references at public settlement, retaining actual
identities through a deferred barrier even if the owner removes them from its
tracking collection. Actual absence remains absence. The helper never creates
a Future, job, event, expected producer count or public result.

For Native DEFAULT, use the actual acquired owner's
`activeBackgroundSearchSyncs` Set. Capture actual Set and member references at
public settlement; inspect that same original Set again at the explicit
barrier. Await the original queued outer maintenance promises, which include
handoff, acquisition, sync and cleanup. Do not wrap, call or replace a sync
method. Existing passive SQL/worker observations continue to authenticate the
inner original execution.

For SDK, join only the actual search-admitted recall Future and actual already
queued publisher work of the current actor-owned original store instance,

## Two distinct declared clocks

Actor wall time remains `1794614400000` ms
(2026-11-14T00:00:00.000Z). Native Date, SDK time.time and the narrow SDK temporal
datetime surface use that actor phase. Only after actual marker-kill termination
and reaping do the pending builder at gate release and fresh recovery processes
use the existing literal `1794614460001` ms phase. Captured call arguments,
revision and prepared state are never refreshed. Monotonic clocks, waits,
watchdogs, debounce and process deadlines remain real.

The source filesystem clock is a separate fixture input, not a replacement
wall time. Initial prepared source files retain
`initialSourceMtimeMs = 1794528000000`. Every declared original API start receives
an independent literal whole-second source tick:

`source atimeMs = source mtimeMs = initialSourceMtimeMs + 1000 * ordinal`.

The manifest contains all resolved integers, not a runtime output-dependent
calculation. Each tick is no later than that original call's declared wall
entry phase. Distinct calls receive distinct ticks even for equal-size edits;
no private writer count, elapsed runtime, observed Native output or expected
producer result supplies a tick.

The exact ordered map is `clock.sourceWriteClock.ticksByCall`. Its keys are
the existing `kind:label` call identities. Every value has exactly
`ordinal`, `actor`, `wallClockNowMs`, `mtimeMs` and `atimeMs`.
Ordinal is the one-based order of original/start API steps, with seedActions
expanded where execute-seed-actions occurs. Await, close, capture, gate and
process-lifecycle steps do not create another public call. A tick does not
predict that its call writes a source or how many original writes occur.

`wallClockNowMs` records call entry. A pending builder retains its original
entry phase and source tick even if its separately declared recovery gate later
advances actor wall time. The new actual wall phase and unchanged original
capture both remain raw.

## Functional filesystem clock protocol

The protocol name is `owned-source-write-clock-v2`. It acts only on a genuine
original write/replacement of an authenticated owned regular workspace source
whose final path ends in .md or .txt. A private staged inode qualifies solely
through its proven association with that actual final source publication.
Initial fixture preparation remains separately dated. SQLite, plugin-state,
JSON stores, evidence, gates, executables and unrelated private files are
untouched.

For an atomic replacement, date the actual staged inode after its final original
successful write/completion and any fsync that original writer actually owns,
before the original rename publishes it. Preserve the original bytes, staged
identity, rename invocation and actual return/error. Some original writers
perform no fsync: preserve that honest absence. The clock fixture adds no fsync
or durability guarantee.

For an in-place write/append, date the genuine owned descriptor after the full
original successful write/completion and any fsync actually owned by that
writer, before descriptor close and original continuation or a declared source
read. Again, do not add a missing fsync. Retain the actual other-reader
visibility interval. This is a bounded profile of the thirteen schedules; an
observed relevant original read of a new byte revision outside the completed
clock receipt invalidates control custody rather than earning an allowance.
An original deletion remains absent; do not recreate its inode for dating.

Both actual atime and mtime are deliberately set to the literal target through
a real utimes operation. This does not promise unchanged atime or other stat.
Preserve full actual stat before/after, including real ctime changes, inode,
mode, size and identity relations. No cross-engine ctime or inode equality is
claimed. All original bytes, syscall returns, errors, public timestamps,
provenance and scores remain observable and unchanged as outputs.

Every receipt binds actual original owner/stack, kind:label, actor/process/
worker causal lineage, staged/final paths and descriptors, original content
hash/bytes, full stat, literal utimes arguments and actual entry/return/error.
Prove its order before original publication/continuation and declared source
reads. Fixture primitives remain distinct from original producer counts.

If one call and final path actually commit two different byte revisions, fail
closed as an unsupported clock control. Do not derive another tick from private
write counts or compress two versions into one. Same-revision repeated receipts
require actual identity proof. This rule predicts no expected write count.

An unowned inode, ambiguous causal call, missing association, unsupported read
interval, clock failure or changed original result is a fixture/guard failure,
not a product error or product conclusion. Preserve its full streams; do not
retry until equal, substitute results, truncate or deduplicate evidence.

## Narrow SDK datetime clock

`clock.sdkDatetimeClock` names module
`memory_core.index.temporal_decay`, binding `datetime`, controlled API `now`
and wallClockSource `executing-actor-declared-wall-phase`.

Use only a fixture proxy for that module binding. Its now(tz=UTC) produces a
genuine original datetime instance representing the declared actor instant.
Constructor and every other class API delegate to the original class, so dated
path parsing keeps its original types and operations. Do not replace datetime
globally, change the production temporal-decay function or switch production
code to time.time.

Raw receipts authenticate original module/class/API identities, proxy identity,
actual arguments, returned original type, timezone and instant, and phase
changes. Source-only tests must prove that an explicit original now_ms bypasses
this fallback, constructors/other APIs delegate, recovery phases work and
monotonic clocks remain real. No ranking or temporal-decay algorithm is copied.

The source reason is concrete: original Native temporal decay uses
`params.nowMs ?? Date.now()`; the SDK counterpart otherwise calls
`datetime.now(tz=UTC)`, which the v1 time.time fixture did not control.
Separately, both original workspace provenance owners take observedAt from
floor(source mtime). Original promotion nowMs does not set that filesystem
metadata. Adding a fabricated artifact-provenance write would introduce a new
ownership fact and does not replace this workspace mtime fallback.
